# 全局搜索服务实施方案

## 首版边界

- 仅索引本机固定 NTFS 卷；不索引网络路径、可移动卷和文件内容。
- 服务以 LocalSystem 身份运行，负责卷枚举、MFT 初始枚举、USN Journal 增量同步和索引持久化。
- BlockBox UI 保持普通用户权限，通过命名管道发送查询并接收分页结果。
- 命名管道 DACL 只授权 LocalSystem、管理员及安装时记录的交互用户 SID；服务端连接后再次校验客户端进程令牌 SID。
- 首次全量索引与增量同步状态通过协议返回，UI 可显示“建立索引中 / 已就绪 / 需要重建”。

## 索引正确性约束

1. 初始枚举前先查询 USN Journal ID 与 `NextUsn`，然后执行 MFT 枚举，完成后回放期间累积的 journal 记录。
2. 持久化每卷的 Volume GUID、Journal ID 和已处理 USN。Journal ID 改变、起始 USN 被删除或索引数据库校验失败时，标记该卷需要重建，不能假装索引仍然完整。
3. 索引记录保存文件引用号、父引用号、名称、目录标记、卷标识和有效状态。路径按需从父引用号还原；删除、重命名和硬链接必须依据 USN reason 更新。
4. 查询只在内存索引上执行，分页返回；路径在返回那一页时按父引用号逐级拼出，不为每条记录保存绝对路径。
5. SQLite 只是崩溃恢复用的持久快照：启动时读入内存索引，USN 回放同时应用到数据库和内存；两者不一致时以 journal 重放修正，不能只更新其中一边。

## 查询路径（内存索引）

服务启动后，查询不再经过 SQLite，也不访问文件系统（`InMemorySearchIndex.cs`）：

- 每个卷一份 `VolumeIndex`。文件名放在 UTF-16 字符池（显示用）和 ASCII 折叠后的 UTF-8 字节池（匹配用，语义等同 SQLite `NOCASE`：只折叠 ASCII，其余按字节比较）。
- 每条硬链接名一条 40 字节记录：文件引用号、父引用号、两段名字的偏移长度、硬链接链下标、目录/墓碑标记。
- 查询是一次顺序内存扫描（`Span<byte>.IndexOf`），命中行交给容量为“页大小 + 1”的堆做有界选择；延迟只随文件总数线性增长，不随命中数增长，翻页用 `(精确匹配, 名称, 卷, 文件号)` 游标在扫描时过滤。
- 空查询是合法请求：列出该分类下的全部文件（不列目录），按名称排序，分页方式与带关键词时完全一致；UI 在搜索框为空、打开面板或切换分类时都会触发。
- `descending` 只反转名称/卷/文件号这几个次序键，精确匹配仍然排在最前；因此倒序也是“顺序分页”，客户端无论升序还是倒序都能把新页追加到列表尾部，滚动位置不会跳变。
- 删除记为墓碑（tombstone），累计超过 6.5 万且超过 25% 时整体压缩；新建、改名、硬链接变更由 USN reason 增量应用。
- trigram FTS5 表和索引已移除：查询不再走 SQL，写入也不再触发三张触发器。

实测数据（本机 4 个卷、235 万条记录、约 1.07 GB 旧库）：加载快照约 4.5 秒、常驻内存约 400 MB；`chrome` 约 80 ms，中文查询约 45 ms，单字母宽查询约 150 ms，宽带翻页约 200 ms。

## 安全与安装

- 服务安装、升级、卸载使用单独的管理员脚本；MSIX 不直接注册 LocalSystem 服务。
- 安装器向服务配置交互用户 SID。命名管道使用显式安全描述符，不使用默认 ACL（默认 ACL 会给 Everyone/匿名用户读取权限）。
- UI 只发送受限 JSON 行协议：`status`、`search`、`cancel`。查询只接受字符串、类型、页大小和排序方向，不允许传入任意路径或命令。
- 服务只读取文件系统元数据，不打开文件内容、不修改 USN Journal 配置、不创建 Journal。

## 实施阶段

1. 定义协议、服务项目及 SCM 生命周期，加入带用户 SID ACL 的命名管道。
2. 实现 FSCTL_ENUM_USN_DATA 初始索引、V2/V3 USN 记录解析、持久化与回放。
3. 加入 Journal 追踪、断点续建、数据库迁移与失败状态。
4. UI 连接服务，加入索引状态、实时搜索、取消/防抖和结果分页。
5. 构建 x64 发布包及管理员安装/卸载脚本，进行虚拟卷/测试卷验证后再在用户机器安装。
